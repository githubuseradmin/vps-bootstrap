# vps-bootstrap

> Один идемпотентный Bash-скрипт, который приводит **свежий Ubuntu/Debian VPS**
> от состояния «root по паролю на порту 22» к разумной, защищённой базовой
> конфигурации — отдельный sudo-пользователь без root, вход по SSH только по
> ключу, фаервол, защита от перебора паролей, автоматические обновления
> безопасности, swap, усиление ядра и опциональный веб/прикладной стек — плюс
> режим **только-чтение для аудита**, чтобы в любой момент проверить (или
> перепроверить) состояние сервера.

Повторный запуск скрипта всегда безопасен: **каждое действие проверяет текущее
состояние, прежде чем что-либо менять**. Никаких полу-применённых состояний,
дублирующихся правил фаервола или перезаписанных конфигов при втором запуске.

```bash
# Посмотреть, что планируется, ничего не меняя
sudo bash bootstrap.sh --dry-run

# Защитить сервер
sudo bash bootstrap.sh

# В любой момент перепроверить состояние — только чтение, ничего не меняется
sudo bash bootstrap.sh --verify     # или: sudo bash harden-check.sh
```

## Зачем

Поднятие нового сервера означает выполнение одного и того же десятка рутинных
задач каждый раз, и именно чувствительные к безопасности (усиление SSH,
фаервол) — те, в которых меньше всего хочется ошибиться. Этот скрипт один раз
кодирует этот чек-лист, выполняет его идемпотентно и — что особенно важно —
**отказывается молча заблокировать вам доступ**. Прежде чем отключить вход по
паролю, он проверяет, что у нового пользователя действительно есть рабочий
SSH-ключ, и проводит вас через проверку второй сессии, прежде чем вы закроете
первую.

Это чистый Bash **без сторонних зависимостей** — только инструменты, которые
уже есть в стандартном образе Ubuntu/Debian (`apt`, `ufw`, `systemd`, `sshd`).

## Что он делает

Каждый шаг — это самостоятельная функция, и он **идемпотентен**:

| # | Шаг | Что делает | Проверка идемпотентности |
|---|-----|------------|--------------------------|
| 1 | **Обновление системы** | `apt-get update && upgrade`, установка базовых утилит | ставит только отсутствующие пакеты |
| 2 | **Пользователь без root** | создаёт `NEW_USER`, добавляет в `sudo`, ставит SSH-ключ | пропускает, если пользователь / ключ уже есть |
| 3 | **Swap** | создаёт swap-файл, если на сервере его нет | пропускает, если swap уже активен |
| 4 | **Часовой пояс и локаль** | задаёт часовой пояс, генерирует локаль | пропускает, если уже настроено |
| 5 | **Фаервол (UFW)** | запрет входящих, разрешение SSH / HTTP / HTTPS, включение | добавляет правило только при его отсутствии |
| 6 | **Усиление SSH** | `PermitRootLogin no`, `PasswordAuthentication no`, опц. смена порта, плюс жёсткие лимиты (`MaxAuthTries 3`, `LoginGraceTime 30`, отключение проброса X11/TCP, тайм-ауты простоя `ClientAlive*`) | пишет drop-in; проверяет `sshd -t` перед перезагрузкой |
| 7 | **fail2ban** | установка + jail для `sshd` (бан после 5 неудач) | пропускает, если файл jail уже есть |
| 8 | **Unattended-upgrades** | включает автоматические обновления безопасности | пропускает, если уже включено |
| 9 | **Усиление sysctl** | SYN cookies, rp_filter, игнор ICMP redirects и т. д. | пропускает, если drop-in существует |
| 10 | **nginx** *(опц.)* | установка + включение + запуск | пропускает установку/запуск, если уже есть/работает |
| 11 | **certbot** *(опц.)* | установка certbot (+ плагин nginx) для Let's Encrypt | ставит только отсутствующие пакеты |
| 12 | **Docker** *(опц.)* | официальный репозиторий Docker CE + добавление пользователя в группу `docker` | пропускает, если Docker уже установлен |
| 13 | **Node.js** *(опц.)* | официальный репозиторий NodeSource, фиксированная мажорная версия (`NODE_VERSION`) | пропускает, если запрошенная мажорная версия уже стоит |
| 14 | **Мониторинг** *(опц.)* | `netdata` (привязан к localhost) или `glances` | пропускает, если уже установлен |

Завершается **итоговой сводкой** и **чек-листом после запуска**.

## Режим аудита (`--verify`) — проверить, не меняя

Запустите аудит состояния/защищённости **только для чтения** в любой момент. Он
проверяет те же области, которые усиливает скрипт — конфигурацию SSH, UFW,
fail2ban, swap, автоматические обновления, sysctl — и печатает отчёт
`PASS` / `WARN` / `FAIL` **ничего не меняя**. Используйте сразу после запуска, по
расписанию (cron) или в CI, чтобы отлавливать дрейф конфигурации.

```bash
sudo bash bootstrap.sh --verify        # или удобная обёртка:
sudo bash harden-check.sh
```

Пример вывода:

```
===== SSH =====
  [PASS] Port                   2222 (moved off 22)
  [PASS] PermitRootLogin        no
  [PASS] PasswordAuthentication no (key-only)
  [PASS] MaxAuthTries           3 — <=3 login attempts per connection
  [PASS] LoginGraceTime         30 — auth must finish within 30s
  [PASS] X11Forwarding          no — X11 forwarding disabled
  [PASS] AllowTcpForwarding     no — TCP forwarding disabled
  [PASS] ClientAliveInterval    300 — idle-session probe interval
  [PASS] ClientAliveCountMax    2 — drop session after 2 missed probes
  [PASS] Drop-in present        /etc/ssh/sshd_config.d/99-vps-bootstrap.conf

===== Firewall (UFW) =====
  [PASS] UFW status             active
  [ -- ] Allowed                2222/tcp 443/tcp 80/tcp

===== fail2ban =====
  [PASS] Service                active
  [PASS] sshd jail              enabled (currently banned: 3)

===== Audit result =====
  PASS: 14   WARN: 1   FAIL: 0
```

Код возврата отражает худшую находку, поэтому его удобно встроить в мониторинг:

| Код | Значение |
|-----|----------|
| `0` | все проверки пройдены |
| `1` | пройдено с предупреждениями |
| `2` | одна или несколько критических проверок провалены |

> Запускайте аудит от **root**, чтобы он мог прочитать живую конфигурацию `sshd`
> и `fail2ban`. Без root он всё равно работает, но часть проверок понижается до
> `WARN`.

## Требования

- **Свежий** Ubuntu (20.04 / 22.04 / 24.04) или Debian (11 / 12) VPS.
- **Доступ root** (вы запускаете скрипт через `sudo` / от root).
- **Ваш публичный SSH-ключ.** Либо:
  - он уже есть у root в `/root/.ssh/authorized_keys` (типично, когда провайдер
    добавил ваш ключ при создании сервера), **либо**
  - вы передаёте его через `SSH_PUBKEY` / `SSH_PUBKEY_FILE` (см. конфигурацию
    ниже).

> Если у нового пользователя **нет** SSH-ключа, скрипт **откажется** отключать
> аутентификацию по паролю и громко предупредит вас — чтобы вы случайно не
> заблокировали себе доступ.

## Быстрый старт

```bash
# 1. Скопируйте скрипт на сервер (scp или вставьте в файл).
scp bootstrap.sh root@SERVER_IP:/root/

# 2. (Рекомендуется) создайте свой конфиг из примера.
cp bootstrap.conf.example bootstrap.conf
$EDITOR bootstrap.conf          # задайте NEW_USER, SSH_PUBKEY, TIMEZONE, ...

# 3. Сначала предпросмотр — НИЧЕГО не меняет:
sudo bash bootstrap.sh --dry-run

# 4. Запуск по-настоящему:
sudo bash bootstrap.sh
```

### Конфигурация

Настройки могут приходить из трёх мест (последнее побеждает):

1. Секция `CONFIGURATION` в начале `bootstrap.sh`.
2. Файл конфигурации — `./bootstrap.conf` подхватывается автоматически, либо
   передайте `--config FILE`. Отталкивайтесь от
   [`bootstrap.conf.example`](./bootstrap.conf.example).
3. Переменные окружения, например:

```bash
NEW_USER=deploy SSH_PORT=2222 INSTALL_DOCKER=true \
  INSTALL_NODE=true NODE_VERSION=20 INSTALL_MONITORING=netdata \
  SSH_PUBKEY="ssh-ed25519 AAAA... you@laptop" \
  sudo -E bash bootstrap.sh
```

Ключевые переменные:

| Переменная | По умолчанию | Значение |
|------------|--------------|----------|
| `NEW_USER` | `deploy` | sudo-пользователь без root (`""` = пропустить) |
| `SSH_PUBKEY` / `SSH_PUBKEY_FILE` | пусто | публичный ключ для установки (иначе копирует ключ root) |
| `SSH_PORT` | `22` | порт SSH |
| `DISABLE_ROOT_LOGIN` | `true` | задать `PermitRootLogin no` |
| `DISABLE_PASSWORD_AUTH` | `true` | вход по SSH только по ключу |
| `TIMEZONE` / `LOCALE` | `UTC` / `en_US.UTF-8` | локализация |
| `SWAP_SIZE` | `2G` | размер swap (`0` = пропустить) |
| `INSTALL_NGINX` / `INSTALL_CERTBOT` | `true` | веб-стек |
| `INSTALL_DOCKER` | `false` | опциональный Docker CE |
| `INSTALL_NODE` / `NODE_VERSION` | `false` / `20` | опциональный Node.js через NodeSource (фикс. мажор) |
| `INSTALL_MONITORING` | `""` | `netdata`, `glances` или пусто (выкл.) |
| `INSTALL_FAIL2BAN` | `true` | защита от перебора паролей |
| `ENABLE_UNATTENDED_UPGRADES` | `true` | автоматические обновления безопасности |
| `LOG_FILE` | `""` | дописывать сюда транскрипт запуска без цветовых кодов |

### Флаги командной строки

| Флаг | Эффект |
|------|--------|
| `--verify`, `--audit` | **аудит только для чтения** — проверить состояние, ничего не меняя (см. выше) |
| `--dry-run` | напечатать все действия, ничего не меняя |
| `--yes`, `-y` | считать «да» для всех подтверждений (неинтерактивно) |
| `--config FILE` | загрузить переопределения конфигурации из `FILE` |
| `--log FILE` | дописать транскрипт запуска без цветовых кодов в `FILE` |
| `--help`, `-h` | показать справку |

## ⚠️ ВАЖНОЕ ПРЕДУПРЕЖДЕНИЕ О БЕЗОПАСНОСТИ — не заблокируйте себе доступ

Этот скрипт может **отключить вход root и аутентификацию по паролю**. Если ваша
настройка ключа неверна, вы можете потерять доступ к собственному серверу и
восстанавливать его придётся через веб-консоль/VNC провайдера.

**Следуйте этому каждый раз:**

1. **Держите текущую SSH-сессию ОТКРЫТОЙ** на всё время запуска и после него.
2. Перед её закрытием **откройте ВТОРОЙ терминал** и войдите как новый
   пользователь:
   ```bash
   ssh -p 22 deploy@SERVER_IP        # используйте -p <SSH_PORT>, если меняли порт
   sudo whoami                       # должно вывести: root
   ```
3. Только когда этот второй вход **и** `sudo` работают, закрывайте первую сессию.

Скрипт помогает вам на каждом шаге, где есть риск блокировки:

- Он **проверяет** конфигурацию SSH через `sshd -t` и отказывается перезагружать
  битую.
- Он **отказывается отключать пароли**, когда у нового пользователя нет
  SSH-ключа.
- Он запрашивает явное подтверждение перед применением усиления SSH и
  **второе, отдельное подтверждение** именно перед переходом на вход только по
  ключу.
- Если вы переносите SSH на нестандартный порт, он **сначала открывает этот порт
  в UFW**, прежде чем сказать `sshd` переключиться — так следующий вход никогда
  не будет отрезан фаерволом.
- После перезагрузки SSH он печатает точную команду `ssh -p <port> user@host`
  для проверки из второго терминала.

Но финальный шаг «проверить вторую сессию» — **на вас**, сделайте его.

> Меняли `SSH_PORT`? Также убедитесь, что **облачный фаервол вашего провайдера**
> (security group в AWS, фаервол Hetzner/DO и т. п.) разрешает новый порт — UFW
> не единственный фаервол перед вашим сервером.

## Что проверить после запуска

Самый быстрый способ — встроенный аудит, который собирает всё нижеперечисленное:

```bash
sudo bash bootstrap.sh --verify     # или: sudo bash harden-check.sh
```

Чтобы проверить вручную:

```bash
# SSH: вход только по ключу как новый пользователь работает (из второго терминала)
ssh -p <SSH_PORT> <NEW_USER>@SERVER_IP

# Фаервол
sudo ufw status verbose

# fail2ban следит за sshd
sudo fail2ban-client status sshd

# Автоматические обновления настроены
cat /etc/apt/apt.conf.d/20auto-upgrades

# Swap активен
swapon --show ; free -h

# Усиление sysctl загружено
sudo sysctl net.ipv4.tcp_syncookies      # -> = 1

# nginx отдаёт (если установлен)
curl -I http://SERVER_IP

# Применённая конфигурация SSH
sudo sshd -T | grep -Ei 'permitrootlogin|passwordauthentication|^port'
```

## Тесты

В проекте есть небольшой набор тестов **без зависимостей** (чистый bash, хост не
требуется). Он проверяет каждый скрипт через `bash -n`, запускает `shellcheck`,
если он доступен, и юнит-тестирует чистые вспомогательные функции (разбор
размеров, счётчики аудита, предикат безопасности SSH-ключа, валидацию
`NODE_VERSION`, гейт подтверждения, идемпотентную запись `set_sshd_option` и
проверки аудита через `sshd -T`):

```bash
bash tests/run-tests.sh
```

```
== result: 39 passed, 0 failed ==
```

`bootstrap.sh` запускает `main` только при прямом выполнении (`if [[
"${BASH_SOURCE[0]}" == "${0}" ]]`), поэтому тесты могут подключить его через
`source` и проверять отдельные функции в изоляции, не трогая систему.

## Замечания по дизайну

- **Примитивы идемпотентности.** Небольшие помощники (`apt_install`,
  `ufw_allow`, `set_sshd_option`, `backup_file`) инкапсулируют паттерн «проверь,
  затем измени», так что функции-шаги читаются как чистый чек-лист.
- **Drop-in для конфигурации SSH.** Усиление пишется в
  `/etc/ssh/sshd_config.d/99-vps-bootstrap.conf`, а не в основной `sshd_config`
  дистрибутива. Это сохраняет чистоту при обновлениях пакетов и упрощает поиск
  или удаление изменений.
- **Честный `--dry-run`.** Каждая изменяющая состояние команда проходит через
  обёртку `run`, поэтому dry-run печатает ровно то, что *произошло бы*, ничего
  не трогая.
- **Резервные копии.** Системные файлы копируются в `*.bak.YYYYMMDD_HHMMSS`
  перед правками.
- **Порядок ради безопасности.** Пользователь и ключ создаются, а фаервол
  открывает SSH *до* усиления SSH — так аутентификацию по паролю невозможно
  отключить раньше, чем появится рабочий путь по ключу.
- **Аудит использует тот же источник истины.** `--verify` читает живую систему
  через `sshd -T`, `ufw status`, `fail2ban-client`, `swapon` и `sysctl`, а не
  перепарсивает файлы, поэтому отчитывается о том, что демоны/ядро *реально*
  делают. Он строго только для чтения и никогда не требует `--yes`.
- **Защита от запуска при source — ради тестируемости.** `main` запускается
  только при прямом выполнении скрипта, что позволяет набору тестов подключать
  его и юнит-тестировать помощники.
